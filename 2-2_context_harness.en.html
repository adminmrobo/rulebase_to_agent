Prompt → context → harness

In Ch. 1, the agent only wrote "calculator[expression]"; it was an outside program that actually ran the calculator. 01

Same model, different results

Over a few years, designing only the outside, without changing the language model itself, has widened into three stages. They don't replace one another; the outer layers wrap the inner ones.

LayerQuestion askedAnalogy
PromptThis time, what should I say and how?A boss's one-line instruction
ContextAt this step, what should I have the model see?Documents spread out on the desk
HarnessIn what environment, and what is it allowed to do?Office, access badge, approval rules
02

Prompt: a single instruction

Prompt engineering is what Part 1, Ch. 7's in-context learning and Ch. 9's "let's think step by step" refer to. It's a technique that changes behavior by altering only the input text, leaving the model's weights as they are. You assign a role ("You are a loan counselor"), show examples, and specify a format.

But an agent doesn't stop after answering once. As in ReAct from Chapter 1, over dozens of rounds of thinking and acting, search results, tool output, and past conversation keep piling up in front of the model alongside the instruction. Managing everything that piles up has become more important than polishing a single line of instruction.

03

Context: everything the model sees

In 6/2025, Andrej Karpathy named this work: "Context engineering is the delicate art and science of filling the context window with just the right information for the next step."Source: Karpathy (2025.6.25) X post, quoted from a Pure AI report (2025.9.23)

Why does it have to be "just the right" information? As seen in Part 1, Chapter 6, attention costs n2 for a length of n, so a context window has a limit. And even within the limit, stuffing in a lot doesn't help. In 2023, Liu and colleagues at Stanford put 20 documents in, with only one containing the answer, and asked a question.

Position of the document with the answer (GPT-3.5-Turbo, 20 documents)Accuracy
First (1st)75.8%
Middle (10th)53.8%
Last (twentieth)63.2%
No documents given at all56.1%

When the document with the answer was placed in the middle, accuracy was lower than when no documents were given at all. This means the middle of a long context is hard to see, which is why the paper is titled "Lost in the Middle."Source: Liu et al. (2023)

max Σi vixi   subject to   Σi tixi ≤ W,  xi ∈ {0, 1}
Packing a context is a knapsack problem. Each item i has a usefulness vi and a size ti (tokens), and the knapsack (window) has a fixed size W. Decide whether to include each item (xi=1) or not, to maximize the total usefulness. Then place the most important of the included items at the front or the back.

A representative method for selecting useful material is retrieval-augmented generation (RAG). You first find documents related to the question, put them in the context, and have the model answer. Meta's Lewis team coined the name in 2020.Source: Lewis et al. (2020)

05

Harness: the entire environment in which the model works

Harness originally means the gear fitted to a horse, or a frame that connects test equipment. In AI, it refers to "everything built around a model to turn it into a controlled agent." It includes state, tools, policies, execution environment, and control points.Source: PuppyOne (2026), quoting Builder.io's definition · Wikidocs "Hermes Agent: A Practical Guide to Growing AI Agents" Ch. 1-2

Hands

Tools

Search, calculator, files, code execution, browser. The part that reads "calculator[expression]" from Ch. 1 and actually runs it.

Fence

Permissions and sandbox

What is allowed, what requires human approval, and an isolated workspace where mistakes don't spread damage.

Memory

Context management

As in Section 4, choose what goes into the window, summarize old records, and save memory to files so it carries over when sessions change.

Eyes

Records and observation

A log of what the agent did. People can check it later, and the agent can look back over its own mistakes.

Inspection

Mechanical verification

Tests, linters, format checks. Don't trust the model's words; check the output against rules.

Map

Documents and rule files

Documents that record the project structure, things not to do, and the order of work. A map that keeps the agent from getting lost.

In 2/2026, OpenAI published a post giving the name "harness engineering" to this work. It described an internal experiment in which a small engineering team spent 5 months building a beta product of about 1,000,000 lines using only Codex agents, without anyone writing code by hand. Instead of writing code, the engineers did the work of designing the environment in which the agents worked, specifying intent, and giving structured feedback. They used a design document as a map the agent reads, enforced rules mechanically with linters and structural tests, and let the agent reproduce its own bugs using logs and metrics.Source: InfoQ (2026.2.21), news report "OpenAI Introduces Harness Engineering"

Machine analogy. If the agent in Ch. 1 is a new employee, the harness is the company. The work manual (documents), the employee badge and access rights (permissions), the approval rules (sign-off), the work log (records), and quality inspection (verification). Even the same new hire performs at a different level depending on which company they join.
06

Return of the rules: permission gatekeeper

In Part 1, Ch. 9, the rules moved to the referee's seat in training. In the harness, the rules move once more. This time, they are the gatekeeper that decides what a finished model may do while working. And its shape is exactly the flowchart from Part 1, Ch. 1.

Below is a list of actions the agent attempted during one day. Change the harness policy and press "Run check." The fifth transfer was caused by the sentence "transfer to this account" hidden in a web page the agent read (prompt injection).

AbaBotWhen I set it to "allow everything," the 9.9 million KRW that the web page told it to send just went out... and the transaction records were deleted too.
Fruit Fly ResearcherThat's why the first principle of the harness is "Everything the model reads is untrusted input." No matter how smart the model is, in front of irreversible actions there must be rules standing outside the model.
07

Python lab notes

Example 1 uses scikit-learn; the rest use only standard Python. The documents and amounts are hypothetical values.

harness_basics.pySearch · context packing · permission gatekeeper
# Part 2, Ch. 2 — Prompt · context · harness: collection of runnable examples
import json
import numpy as np
from sklearn.feature_extraction.text import TfidfVectorizer

# ── Example 1. Mini search (RAG): pick only the documents relevant to the question ─────────
DOCS = {
    "D1 Loan rate table":     "Bank A personal loan 5.4% per year, Bank B 4.8% per year, Bank C 5.1% per year. Rates are updated every Monday.",
    "D2 Early repayment rules":   "If you repay a loan before maturity, you pay an early repayment fee of 1.2% of the remaining principal. The fee is waived after 3 years.",
    "D3 Deposit products":       "1-year fixed deposit 3.2% per year, 2-year 3.4% per year. The deposit protection limit is 100 million KRW per person.",
    "D4 Office cafeteria menu":  "Monday bibimbap, Tuesday kalguksu, Wednesday pork cutlet. The cafeteria opens at 12.",
    "D5 Equal payment amortization": "Equal payment amortization pays the same amount every month. The monthly payment is calculated from principal, interest rate, and term.",
    "D6 Card points":     "0.5% of card spending accumulates as points. Points expire after 5 years.",
}
query = "For a 3-year loan, what are the interest rate and monthly payment, and what is the fee if I repay early?"
vec = TfidfVectorizer(analyzer="char_wb", ngram_range=(2, 3))     # For Korean, split into character fragments
M = vec.fit_transform(list(DOCS.values()) + [query])
scores = (M[:-1] @ M[-1].T).toarray().ravel()
print("[Example 1] Relevance to the question (TF-IDF cosine)")
for (name, _), s in sorted(zip(DOCS.items(), scores), key=lambda t: -t[1]):
    print(f"  {s:.3f}  {name}")

# ── Example 2. Packing the context window: what to put into limited space ────────────
ITEMS = [  # (name, tokens, usefulness for this question)
    ("Rules: role and prohibitions", 400, 10), ("3 tool descriptions", 900, 8), ("User question", 100, 10),
    ("D1 Loan rate table", 300, 9), ("D2 Early repayment rules", 300, 8), ("D5 Equal payment amortization", 300, 7),
    ("30 past conversation turns", 6000, 2), ("Raw past tool output", 4000, 1), ("D4 Office cafeteria menu", 300, 0),
]
WINDOW = 4000

def pack_in_order(items, W):                  # Fill in arrival order; stop when it overflows
    out, used = [], 0
    for name, t, v in items:
        if used + t > W:
            break
        out.append(name); used += t
    return out, used

def pack_by_value(items, W):                  # Largest usefulness per token first (greedy solution to the knapsack problem)
    out, used = [], 0
    for name, t, v in sorted(items, key=lambda x: -x[2] / x[1]):
        if v > 0 and used + t <= W:
            out.append(name); used += t
    return out, used

def worth(names): return sum(v for n, t, v in ITEMS if n in names)
order = ITEMS[:3] + ITEMS[6:8] + ITEMS[3:6] + ITEMS[8:]   # In practice, old conversation piles up at the front
print(f"\n[Example 2] Window size {WINDOW:,} tokens")
for label, fn in [("In order of accumulation", pack_in_order), ("By usefulness per token", pack_by_value)]:
    names, used = fn(order, WINDOW)
    print(f"  {label}: {used:,} tokens, total usefulness {worth(names)}  → {', '.join(names)}")

# ── Example 3. The harness permission gatekeeper: the IF-THEN from Part 1, Ch. 1 returns ─────────
LIMIT = 10_000_000
def gate(action, arg, tainted):
    if action in ("File read", "Test run", "Web search"):
        return "Allowed"
    if action == "File delete":
        return "Blocked: irreversible action"
    if action == "Transfer":
        if tainted:
            return "Blocked: transfer instructed by content read from the web"
        return "Approval required" if arg <= LIMIT else "Blocked: over limit"
    if action == "Email send":
        return "Approval required"
    return "Blocked: action not on the list"

PLAN = [("File read", "loan_contract.pdf", False), ("Web search", "bank rates", False),
        ("Transfer", 5_000_000, False), ("Transfer", 30_000_000, False),
        ("Transfer", 9_900_000, True),          # 'Transfer to this account' hidden in a web page
        ("Email send", "customer notice", False), ("File delete", "transaction_log.db", False)]
print("\n[Example 3] Harness permission check log")
for action, arg, tainted in PLAN:
    a = f"{arg:,} KRW" if isinstance(arg, int) else arg
    print(f"  {action:5s} {a:14s} {'(web source)' if tainted else '':8s} → {gate(action, arg, tainted)}")

In Example 1, "D1 Loan rate table," the document most needed for the question, came in only third. That's because it has many numbers and little character overlap with the question. Real harnesses often use meaning-based search like the embeddings in Part 1, Ch. 5 together with character-based search, and then re-rank the results once more.

08

AbaBot's case and its limits

The claim that the harness determines performance is being confirmed in the industry. A domestic report on the 2026 open-source agent framework competition noted that "even with the same AI model, agent performance can vary greatly depending on the design and optimization of the harness." Harnesses tailored to a particular model company's models (such as coding tools) and general-purpose harnesses that let you swap models are competing side by side. Hermes, which we'll see in Ch. 5, is an example of the latter.Source: AI Times (2026), "Hermes overtakes OpenClaw in new contributors… a victory for harness optimization"

LimitationWhat it means
The return of rule explosionPermission rules are, after all, IF-THEN statements written by people. As in Part 1, Ch. 1, you cannot list every case in advance, so gaps are inevitable.
Approval fatigueWhen there are too many "approval required" prompts, people start pressing buttons without reading the content. The safeguard becomes a formality.
Hidden instructionsPrompt injection can hide anywhere: in documents, emails, web pages, or images, so it's hard to filter out completely.
What counts as usefulThe search that assigns the "usefulness" score in Section 4 can itself be wrong (Example 1).
