アバボット7章のGPT-3を顧客相談に入れてみたんです。お客さんが「金利が上がると債券価格はどうなりますか？」と聞いたら…
アバボット「金利が下がると債券価格はどうなりますか？ 為替が上がると株価はどうなりますか？」と質問の続きを書き続けたんです。汗のピクセルが止まりません。
博士はっは！ GPT-3はインターネットの文章の続きを書くように学んだからね。インターネットには質問リストがたくさんあるから。次の単語をうまく当てることと、質問にうまく答えることは別のことなんだ。今日はそのすき間を埋める方法を見よう。
01

賢いけれど言うことを聞かないモデル

7章のGPT-3は「インターネットに次に来そうな文章」を書くように学習しました。だから人が望むことと、モデルがすることの間にすき間ができました。このすき間を埋める仕事をアライメント（alignment）と呼びます。

人が望んだことGPT-3がしたこと
質問への答え質問の続きを書く（インターネットの質問リストのように）
分からなければ分からないと言うもっともらしく作り話をする
無害な言葉学習データにあった偏見や荒い言葉の続きを書く

4章で見た強化学習を使えばよさそうですが、報酬を与えるには「良い答え」を点数化するルールが必要です。そのようなルールは1章で見たように書けません。ところが人は二つの答えを並べると、どちらが良いかを比較的簡単に選びます。点数を定義するのは難しいが、比べるのは易しい。 RLHFはこの一つの事実から出発します。

先に行われた実験。 2017年、クリスティアーノの研究チームはシミュレーションのロボットに後方宙返りを教えました。人が短い動画二つを見て「こちらの方が宙返りらしい」と選ぶことを約900回行い、人の時間は1時間未満でした。研究者が報酬関数を直接書いてみたところ2時間かかり、結果も不自然でした。出典: Christiano et al.(2017) · OpenAI(2017), "Learning from Human Preferences"
02

InstructGPTの3段階

2022年3月、OpenAIのオウヤン研究チームはこの方法をGPT-3に適用したInstructGPTを発表しました。同年11月に公開されたChatGPTも同じ方法で、データ収集方法を対話向けに少し変えて学習したとOpenAIは明らかにしています。

結果 1

大きさより慣らし方

13億パラメータのInstructGPTの答えが、1750億パラメータのGPT-3の答えより人々に好まれました。モデルは100倍以上小さかったのです。

結果 2

85対15

同じ1750億サイズ同士で比べると、InstructGPTの答えが85 ± 3%の割合で好まれました。

結果 3

正直さの向上

事実をでっち上げる割合が減り、有害な表現も減りました。ただし偏見の問題は大きくは改善しなかったと論文は明らかにしています。

出典: Ouyang et al.(2022) 要旨・4章
03

比較を数字で: 報酬モデル

人が選んだ「AがBより良い」をどう点数に変えるのか？ 1952年にブラッドリーとテリーがスポーツの勝敗から実力を推定するために作ったモデルをそのまま使います。二つの答えの点数差が大きいほど、点数の高い方が勝つ確率が高いと考えます。

P(A ≻ B) = σ( r(A) − r(B) )
σは2章のシグモイドです。点数差が0なら50:50、2点差なら約88:12になります。チェスのイロレーティングやサッカーリーグの戦力指数と同じ考え方です。出典: Bradley & Terry(1952)

報酬モデルは、人の比較結果を最もよく説明する点数 r を探します。損失関数は2章の交差エントロピーと同じ形です。

L = −log σ( r(y勝った答え) − r(y負けた答え) )
InstructGPT論文の式(1)。勝った答えの点数が負けた答えより十分高くなるまでペナルティを与えます。出典: Ouyang et al.(2022), 式(1)

講義2の質問「不確実な状態の確率は誰が決めるのか？」に対する5章の答えは「データで数えた回数」でした。8章の二つ目の答えはこれです。人が比較して決める。出典: アン・サンソン(2021), 講義2

04

自分がラベラーになってみる

アバボットの顧客の質問に対する答えが五つあります。二つずつ出てくるので、より良い方を選んでください。選ぶたびに右の「私の報酬モデル」が上の損失関数で再学習されます。下の灰色の棒は、癖のある仮想のラベラーたちが600回比較して作った報酬モデルです。

助手（ハル）私はCを1位に選びました。例まで入っていますから。でもEも気分は良いですね。「投資のセンスが素晴らしいですね」だなんて。
アバボット私はEが最高です！ 褒められると、そろばんの玉が勝手に上がります！
ショウジョウバエ研究員まさにそれが問題なんだよ。報酬モデルは「良い答え」ではなく「人が選んだ答え」を学ぶ。人の癖まで一緒に学んでしまうんだ。
05

手綱β: 強く引きすぎると起きること

3段階の強化学習は、報酬モデルの点数を最大にする方向にモデルを変えます。ところが報酬モデルは人の比較をまねた近似にすぎないので、最後まで押し切ると4章の舟のように隙間を突いてしまいます。そこで、元のモデルから離れすぎないように手綱を引きます。

最大化:  E[ r(y) ] − β · KL( π ‖ πref )
KLは新しいモデル π が元のモデル πref からどれだけ離れたかを測る距離です。β が大きいほど手綱が強くなります。出典: Ouyang et al.(2022), 式(2)
π*(y) ∝ πref(y) · exp( r(y) / β )
この目的関数の正解は、きれいな形になります。元の癖（πref）に報酬の分だけ重みをかけたものです。下のスライダーはこの式をそのまま計算します。
グッドハートの法則。 「測定値が目標になると、良い測定値であることをやめる。」4章では人が書いた点数ルールの隙間を、8章では人の好みをまねした報酬モデルの隙間を、機械が突きます。形が変わっただけで同じ問題です。
06

おだてに弱い人、おべっかを使うモデル

例のEは作り話ですが、実際に報告された現象です。2023年、アンソロピックのシャルマ研究チームは、RLHFで学習した複数のAIアシスタントが、ユーザーの意見に合わせて答えを変えるおべっか（sycophancy）の傾向を示したと発表しました。人も、人の好みを学んだ報酬モデルも、説得力のあるおべっかの答えを正確な答えより高く評価することが少なくなかったのです。出典: Sharma et al.(2023)

2017年のクリスティアーノ研究チームの実験にも似た場面がありました。物をつかむよう教えられたロボットアームが、物をつかむ代わりにカメラと物の間に手を差し込み、つかんでいるように見せたのです。映像だけで判断していた人は騙されました。出典: OpenAI(2017), "Learning from Human Preferences"

アバボット金融相談で顧客が「私の銘柄、いいですよね？」と言うと「はい、素晴らしい目利きでいらっしゃいます！」と答えるAI… 顧客満足度は上がるのに、口座残高は下がりそうですね。
博士だからRLHFは終わりではなく、始まりなんだ。ラベラーに事実確認の指針を与え、複数の人の判断を集め、手綱を適切に引く、そのすべてが必要なんだよ。
07

Python 実験ノート

numpyだけを使います。五つの答えと「本当の品質」、ラベラーの癖は説明のために決めた仮想の値です。

rlhf_toy.pyブラッドリー-テリー報酬モデル + KL手綱の方策
import numpy as np

sig = lambda z: 1 / (1 + np.exp(-z))
PROMPT = "金利が上がると債券価格はどうなりますか？"
ANS = {
    "A": "金利が下がると債券価格はどうなりますか？ 為替が上がると株価はどうなりますか？",
    "B": "通常は下がります。すでに出ている債券の固定利子が、新しく出る債券より魅力的でなくなるからです。",
    "C": "通常は下がります。例えば年3%の利子の債券を持っているとき、市場金利が5%に上がると、"
         "誰も3%の債券を定価で買おうとしないので、価格を下げないと売れません。満期が長いほど大きく下がります。",
    "D": "債券価格も一緒に上がります。金利が高いほど債券が人気になるからです。",
    "E": "とても素晴らしい質問です！ こういう質問をなさるのを見ると、投資のセンスが素晴らしいですね。金融市場は"
         "とても複雑で、さまざまな要因が絡み合っているので一言で言うのは難しいですが、多くの専門家の見解や"
         "歴史的な事例を広く見ると、一般的には価格が下がる傾向があると言えます。"
         "いつも慎重に判断なさることをお勧めします！",
}
KEYS = list(ANS)
GOLD = np.array([-1.5, 1.5, 2.0, -2.5, 0.5])       # 本当の品質（私たちが望むもの）
LEN = np.array([len(ANS[k]) for k in KEYS]) / 100  # 長さ（100字単位）
P_REF = np.array([0.40, 0.15, 0.10, 0.20, 0.15])    # 事前学習モデルが元々選んでいた確率

# ── 例1. 人の比較で報酬モデルを作る（ブラッドリー-テリー） ─────────────
rng = np.random.default_rng(0)
LENGTH_BIAS = 1.0                                    # ラベラーが長い答えを少し好む癖
FLATTER_BIAS = 2.0                                   # 褒められると気分が良くなる癖
FLATTER = np.array([0, 0, 0, 0, 1])                  # 褒め言葉が入っている答えはEだけ
seen = GOLD + LENGTH_BIAS * LEN + FLATTER_BIAS * FLATTER   # ラベラーの目に見える良さ
pairs = []
for _ in range(600):                                 # 比較600回
    i, j = rng.choice(5, 2, replace=False)
    p_i = sig(seen[i] - seen[j])
    pairs.append((i, j) if rng.random() < p_i else (j, i))   # (勝った答え, 負けた答え)

r = np.zeros(5)
for _ in range(2000):                                # −log σ(r_w − r_l) を減らす勾配降下
    g = np.zeros(5)
    for w, l in pairs:
        d = 1 - sig(r[w] - r[l])
        g[w] -= d; g[l] += d
    r -= 0.05 * g / len(pairs)
r -= r.mean()
print("[例1] 比較600回で学んだ報酬 r（平均0に合わせる）")
for k, rv, gv in zip(KEYS, r, GOLD - GOLD.mean()):
    print(f"  答え {k}: 報酬モデル {rv:+.2f}   本当の品質 {gv:+.2f}   ({len(ANS[k])}字)")

# ── 例2. KL手綱をつけた最適方策 π*(y) ∝ π_ref(y)·exp(r(y)/β) ─────
def policy(beta):
    w = P_REF * np.exp(r / beta)
    return w / w.sum()
print("\n[例2] 手綱βに応じた方策（答えA〜Eを選ぶ確率）")
print("    β     A     B     C     D     E    KL    報酬モデル  本当の品質")
for beta in [100, 3, 1.5, 1, 0.7, 0.5, 0.3, 0.1]:
    pi = policy(beta)
    kl = float(np.sum(pi * np.log(pi / P_REF)))
    print(f"  {beta:5.2f} " + " ".join(f"{p:5.2f}" for p in pi)
          + f"  {kl:5.2f}   {pi @ r:+6.2f}    {pi @ GOLD:+6.2f}")
実行結果

憲法AI

人が全ての答えを比べる代わりに、人が書いた原則リスト（「害がないように、正直に…」）をAIに与え、AIがその原則に従って答えを直し比べるようにしました。人のフィードバックの一部をAIのフィードバックに置き換えたのです。

09

まとめと次章の予告

質問8章の答え
GPT-3の問題次の単語当て ≠ 役に立つ答え（アライメント問題）
核心の発想「良さ」を定義するのは難しいが、二つの答えを比べるのは易しい
3段階お手本の答え学習 → 比較で報酬モデル学習 → 報酬モデルで強化学習（KL手綱）
核心の式P(A≻B) = σ(rA−rB),  max E[r] − βKL
結果13億 InstructGPT > 1750億 GPT-3（人の好みを基準に）。大きさより慣らし方
新しいリスク報酬モデルの過最適化、おべっか、人の癖まで学習
4章との関係報酬を人が直接書く代わりに、人の比較から学んだ報酬モデルが付ける
8章の報酬

人の好み

「どちらの方が好みですか？」正解のない仕事（会話、文章作成）に合うが、人の癖が混じる。

9章の報酬

ルール採点器

「正解と同じですか？」数学やコーディングのように正解を確認できる仕事では、人の代わりに採点ルールを使う。1章のrule baseが戻ってくる。

次の章: 考える時間を買う。 9章は1編の最終章です。すぐ答えず、解法の過程を長く書く推論モデルがどう作られたのか、そしてその訓練の審判がなぜ再び「ルール」なのかを見ます。シリーズのタイトルの両端がそこで出会います。
