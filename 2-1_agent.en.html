Part 2 · Ch. 1 From LLM Reasoning Models to Working AI

Agent models:
AI that learned to act

At the end of Part 1, AI learned to think. It wrote out solutions, checked them, and tried multiple paths. But no matter how well it thought, it could not look up bank interest rates or edit a file. Part 2 is the story of a thinking AI gaining hands and feet so it can finish the work.

01

AI that answers, AI that works

Do you remember the diagram from Part 1, Ch. 4? When an agent acts, the environment changes, and the agent observes the result to choose its next action. Back then, the agents were a maze robot and a Go AI. In Part 2, a language model takes the same place.

Agent = language model + tools + iteration
It does not answer once and stop. It repeats "think → act → observe" until the job is done. This chapter covers the language model side; the next chapters cover the frame that wraps the tools and the iteration (the harness and the loop).
Machine analogy. If the Part 1 reasoning model was an exam taker given scratch paper, the Part 2, Ch. 1 agent is a new hire on their first day. They don't solve problems only in their head: they log into the company system, open Excel, ask colleagues questions, and finish the job.
02

ReAct: alternating thought and action

In 2022, a research team led by Shunyu Yao at Princeton and Google published a method for having a language model alternate between Thought and Action. When the model writes an action, a program actually runs the tool and returns the result to the model as an Observation. The name ReAct combines Reasoning and Acting.

TestAction onlyImitation learningReAct
ALFWorld (doing household chores in a virtual home, success rate)453771
WebShop (buying items that match criteria in a virtual online store, success rate)30.129.140

The paper also reported honest results. On HotpotQA, which answers questions by searching Wikipedia, using ReAct alone scored lower than chain-of-thought alone (27.4 vs. 29.4), and combining the two was best (35.1). But ReAct's solutions were grounded in search results, and the authors reported that fabricated facts became noticeably less frequent.Source: Yao et al. (2022) · Google Research blog, "ReAct: Synergizing Reasoning and Acting in Language Models"

P = 100 million won, r = 0.048 ÷ 12 = 0.004, n = 36. If a language model does this calculation in its head (as tokens), it easily gets it wrong, just like AbaBot in Part 1, Ch. 9. Handing it to a calculator is the right answer.

04

Up to handing over the tools

ReAct was a prompting method that showed a few examples. In the years that followed, tool use became a capability models learn and a standard feature of services.

2023.2 · Meta

Toolformer

The model inserted calculator, search, and translation calls into sentences on its own, then trained only on the calls whose results helped it predict the next word. In effect, it learned for itself when to call a tool.

2023.6 · OpenAI

Function calling

Developers provide a list of functions the model can use, and the model returns a structured request asking to call a function with specific values. It standardizes the "calculator[expression]" from Section 3.

2024.10 · Anthropic

Computer use

Models were given tools to take screenshots, move the mouse, and type on the keyboard. Programs built for people were made to be used the way people use them.

Sources: Schick et al. (2023) · OpenAI (2023.6.13), "Function calling and other API updates" · Anthropic (2024.10.22), "Introducing computer use"
05

Actions are learned with reinforcement learning too

In Part 1, Ch. 9, the reasoning model developed a habit of thinking through rule-based grading of "+1 if correct." Agents work the same way. The difference is that what gets graded is not one line of an answer but the entire multi-step job. If the task is to fix code, the rule checks whether the job is finished, such as "+1 if all tests pass after the fix."

G = r1 + γr2 + γ2r3 + ⋯ + γT−1rT
This is exactly the "sum of future rewards" from Part 1, Ch. 4. Usually the intermediate step rewards r1 … rT−1 are 0 (or a small cost each time a tool is called), and a large reward comes at the end, depending on whether the job was finished. The model has to figure out for itself which step's action contributed to success.

Example 3 imitates this on a very small scale. For each kind of problem, it lets the model choose a tool, gives +1 for finishing the job, and deducts a small penalty for each tool call. Nobody taught it "use a calculator for math problems."

After 3,000 practice runsDirect answerCalculatorSearch
Math problem1%98%1%
Current information0%0%99%
General knowledge96%1%4%

What matters is that for "general knowledge," it learned not to use a tool. Tools aren't free, so calling them only when needed is also a skill.

A real test: SWE-bench. In 2023, a Princeton team led by Jimenez collected 2,294 real GitHub issues from 12 popular Python repositories and built a test: "Read the issue, fix the code, and make the tests pass." When it was released, the best-performing model (Claude 2) solved 1.96% of them. The benchmark later became a leading measure in the competition among coding agents, and the rule-based grading of passing tests is still used as the reward for training agents.Source: Jimenez et al. (2023)
06

A trap that grows as the steps get longer

In Part 1, Ch. 7, we saw that when all five digits must be correct for an answer to count as right, accuracy drops sharply to p5. An agent's job is a magnified version of this. A 20-step job only finishes if there are no mistakes across 20 steps in a row.

Probability of success through the end = pk   (per-step success rate p, number of steps k)
A 95% per-step success rate looks quite reliable, but over 20 steps it is 35.8%, and over 50 steps it is 7.7%.

In 2025, the research organization METR measured this problem from the opposite direction. They gathered software tasks ranging from ones that take a human a few minutes to ones that take several hours, and for each model measured the length of task (in human time) that the AI could complete with 50% probability. From 2019 to early 2025, this length doubled roughly every 7 months. At the time, Claude 3.7 Sonnet's 50% length was about 1 hour, and its 80% length was about 15 minutes. Even for the same model, the length of tasks it can do "reliably" is much shorter.Source: Kwa et al. (2025), METR, "Measuring AI Ability to Complete Long Tasks"

Fruit Fly ResearcherDoubling every 7 months sounds impressive, but as in Part 1, Ch. 7, you shouldn't just stretch out the end of the graph. And remember that the tasks they measured lean heavily toward software work.
07

Python lab notes

Uses only the standard library re and numpy. The language model in Example 1 is a fake driven by a script, but tool execution and calculations are real.

agent_basics.pyReAct · success probability · learning tool selection
# Part 2, Ch. 1 — Agent models: collection of runnable examples
import json, re
import numpy as np

# ── Example 1. ReAct loop: repeat think → act → observe ─────────────────
RATES = {"Bank A": 5.4, "Bank B": 4.8, "Bank C": 5.1}            # hypothetical loan rate table (annual %)

def lookup_rates(_):                                          # Tool 1: rate lookup
    return ", ".join(f"{k} {v}%" for k, v in RATES.items())

def calculator(expr):                                         # Tool 2: calculator
    if not re.fullmatch(r"[0-9+\-*/(). ]+", expr):            # only digits and operators allowed
        return "Error: not an arithmetic expression"
    return f"{eval(expr):,.0f}"

TOOLS = {"rate_lookup": lookup_rates, "calculator": calculator}

def fake_llm(history):
    """A 'fake LLM' for illustration. It imitates what a real LLM does with a pre-written script."""
    n_obs = sum(1 for h in history if h.startswith("Observation"))
    if n_obs == 0:
        return "Thought: I don't know the rates, so I need to look up each bank's rate first.\nAction: rate_lookup[]"
    if n_obs == 1:
        return ("Thought: The lowest rate is Bank B at 4.8%. Monthly rate r=0.048/12=0.004, n=36 months.\n"
                "Action: calculator[100000000*0.004*(1.004**36)/((1.004**36)-1)]")
    last = history[-1].replace("Observation: ", "")                  # read the last observation and answer
    return f"Thought: The calculation is done, so I can answer.\nFinal answer: Bank B (4.8% per year), monthly payment about {last} won"

def run_agent(question, max_steps=5):
    history = [f"Question: {question}"]
    for step in range(1, max_steps + 1):
        out = fake_llm(history)
        history.append(out)
        print(f"  [Step {step}] " + out.replace("\n", "\n          "))
        if "Final answer" in out:
            return history
        m = re.search(r"Action: (\S+?)\[(.*)\]", out)
        obs = TOOLS[m.group(1)](m.group(2))                     # the harness actually runs the tool
        history.append(f"Observation: {obs}")
        print(f"          Observation: {obs}")
    return history

print("[Example 1] ReAct agent")
run_agent("I want to borrow 100 million won for 3 years (36 months) with equal principal-and-interest payments. Which bank is cheapest, and what is the monthly payment?")

# ── Example 2. Success probability over many steps: small mistakes pile up ───────────────
print("\n[Example 2] Probability of success through the end, for per-step success rate p and k steps")
print("    p     k=5   k=10   k=20   k=50  | check-and-retry (k=20)")
for p in [0.90, 0.95, 0.99]:
    plain = [p ** k for k in [5, 10, 20, 50]]
    d = 0.8                                                     # probability of noticing a mistake
    p_retry = p + (1 - p) * d * p                               # if noticed, try once more
    print(f"  {p:.2f} " + " ".join(f"{x:6.1%}" for x in plain) + f"  | {p_retry ** 20:6.1%}")

# ── Example 3. Learning which tool to use from rewards (Ch. 4 reinforcement learning, again) ──────
KINDS = ["Math problem", "Current info", "General knowledge"]
TOOLN = ["Direct", "Calculator", "Search"]
SUCCESS = np.array([[0.40, 0.95, 0.30],        # math: the calculator is most accurate
                    [0.10, 0.05, 0.90],        # current info: only search works
                    [0.85, 0.10, 0.80]])       # general knowledge: answering directly is fine (tools waste time)
COST = np.array([0.0, 0.05, 0.10])             # calling a tool costs time and money (penalty)
rng = np.random.default_rng(0)
theta = np.zeros((3, 3))
for t in range(3000):
    k = rng.integers(3)
    pi = np.exp(theta[k]) / np.exp(theta[k]).sum()
    a = rng.choice(3, p=pi)
    reward = float(rng.random() < SUCCESS[k, a]) - COST[a]      # did the job get done? (rule-based grading)
    baseline = pi @ (SUCCESS[k] - COST)
    grad = -pi; grad[a] += 1
    theta[k] += 0.1 * (reward - baseline) * grad
print("\n[Example 3] Tool selection probability by problem type after 3,000 practice runs")
print("              Direct  Calculator   Search")
for k, name in enumerate(KINDS):
    pi = np.exp(theta[k]) / np.exp(theta[k]).sum()
    print(f"  {name:8s} " + " ".join(f"{x:7.0%}" for x in pi))

P, r, n = 100_000_000, 0.004, 36
print(f"\nCheck: monthly payment = {P * r * (1 + r) ** n / ((1 + r) ** n - 1):,.0f} won")

AbaBot's worries and limits

AbaBotGreat! So I just give this agent my account transfer permission and tell it, "Go get me the cheapest loan on your own"?
Fruit Fly ResearcherReally? You just said a 20-step job has a 36% success rate. Who takes responsibility for what happens in the other 64%? And what if a webpage the agent reads secretly says, "Send money to this account"?
DoctorThat's exactly prompt injection. What the agent observes is untrusted input, and the model can mistake it for an instruction. So a working AI needs safeguards just as much as it needs hands and feet.

Appendix

Running it on the real API

The experiment notes in this chapter imitated the language model with a fake function. Below is a minimal example that moves the same ReAct loop onto the real Claude API's tool use. It has three parts: ① give the tool's name, description, and input format; ② your own code does the actual calculation; and ③ when the model requests a tool, return the result as a tool_result and repeat until the final answer comes out.

real_agent.pyanthropic SDK · requires an API key
# Part 2, Ch. 1 appendix: a minimal agent loop running on the real API
# Requirements: pip install anthropic, environment variable ANTHROPIC_API_KEY
import anthropic

client = anthropic.Anthropic()          # The API key is read from an environment variable (do not write it in the code)
MODEL = "claude-opus-5-5"               # Model name in use. Check the docs for the latest name

# ① Tool definition: name, description, input format (JSON schema). The model decides when to use it from this description alone
TOOLS = [{
    "name": "monthly_payment",
    "description": "Calculates the monthly payment (KRW) of an equal-installment loan.",
    "input_schema": {
        "type": "object",
        "properties": {
            "amount": {"type": "number", "description": "Loan principal (KRW)"},
            "annual_rate": {"type": "number", "description": "Annual interest rate. For 4.8%, enter 0.048"},
            "months": {"type": "integer", "description": "Number of repayment months"},
        },
        "required": ["amount", "annual_rate", "months"],
    },
}]

# ② The actual work is done by my code. The model only requests that "this tool be called with these values"
def monthly_payment(amount, annual_rate, months):
    r = annual_rate / 12
    return round(amount * r * (1 + r) ** months / ((1 + r) ** months - 1))

def run_tool(name, args):
    if name == "monthly_payment":
        return str(monthly_payment(**args))
    return f"Unknown tool: {name}"

# ③ ReAct loop: call the model → if it requests a tool, run it and return the result → repeat until a final answer appears
def agent(question, max_steps=5):                     # Stop condition: maximum number of iterations (Part 2, Ch. 3)
    messages = [{"role": "user", "content": question}]
    for step in range(max_steps):
        resp = client.messages.create(model=MODEL, max_tokens=1024, tools=TOOLS, messages=messages)
        if resp.stop_reason != "tool_use":            # No more tool calls: this is the final answer
            return "".join(b.text for b in resp.content if b.type == "text")
        messages.append({"role": "assistant", "content": resp.content})
        results = []
        for b in resp.content:
            if b.type == "tool_use":
                out = run_tool(b.name, b.input)
                print(f"  [action {step + 1}] {b.name}({b.input}) → {out}")
                results.append({"type": "tool_result", "tool_use_id": b.id, "content": out})
        messages.append({"role": "user", "content": results})  # Return the observation
    return "Iteration limit exceeded; handing off to a person."

if __name__ == "__main__":
    print(agent("If I borrow 100 million KRW at 4.8% per year for 36 months, how much do I have to repay each month? How much less if it's 40 months?"))
Loop check (result from testing with a fake response)
  [action 1] monthly_payment({'amount': 100000000.0, 'annual_rate': 0.048, 'months': 36}) → 2988118
  [action 1] monthly_payment({'amount': 100000000.0, 'annual_rate': 0.048, 'months': 40}) → 2710317
To be honest about this. The output above only confirms that the loop runs correctly, using a fake client that imitates the shape of API responses. When you ask a real model, whether it calls two tools at once or one at a time, and how it phrases the final answer, will vary each time. The monthly payment of 2,988,118 KRW for 36 months matches the value in this chapter's experiment notes. Model names and pricing change, so check the official docs before you use this.

In practice, you would add the Part 2, Ch. 2 permission gate (dangerous tools require human approval), the Ch. 3 verifier (recalculate the answer to check it), and a cost budget. The max_steps in the code above is the simplest of these stop conditions.

Source: Claude Platform Docs, "Handling stop reasons" (tool_use · tool_result format)
