# 강의자용 안내: rule base에서 일하는 AI까지

2026-11-03 · 안상선 ((주)M-Robo 대표)

## 이 안내서의 쓰임

해설 시리즈 15개 장을 대학 정규 과목(15주)이나 기업 특강(4회)에 그대로 끼워 쓰기 위한 강의자용 안내입니다. 장마다 학습 목표, 수업 흐름, 토론 질문, 과제 아이디어, 학습자가 자주 빠지는 오개념을 정리했습니다.

시리즈는 두 편입니다. [1편 「플로우 차트의 rule base가 LLM 추론 모델이 되기까지」](../1-1_rulebase.html)(9장)는 규칙 기반에서 추론 모델까지, [2편 「LLM 추론 모델이 일하는 AI가 되기까지」](../2-1_agent.html)(6장)는 에이전트에서 자가개선 루프까지 다룹니다. 전체 목차는 [첫 화면](../index.html)과 [2편 6장](../2-6_reinforcement_thread.html#s9)에 있습니다.

모든 장은 같은 틀을 씁니다.

- 캐릭터 대화(박사·조수 하루·초파리 연구원·주판봇)로 문제 제기
- 10개 안팎의 절: 개념 → 수식 → 직접 조작하는 도판 → 파이썬 실험 노트 → 현장 사례와 한계 → 정리
- 장 끝: 확인 문제 3개(개념·수치 읽기·적용), 이전/다음 장 이동 링크
- 1편 각 장 목차 아래: 약 10분짜리 "빠른 경로"

한 장의 본문은 약 9천~1만 2천 자이고, 정독에 25~35분, 빠른 경로로 약 10분이 걸립니다.

## 수업 설계안

15주 과목은 한 주에 한 장을 기본으로 하고, 분량이 가벼운 2편 4·5장을 한 주에 묶어 중간 점검 주를 만듭니다. 주당 150분(강의 90분 + 실습·토론 60분)을 가정했습니다.

| 주 | 다루는 장 | 실습·활동 |
| --- | --- | --- |
| 1 | 오리엔테이션 · 1편 1장 규칙 기반 | 대출 심사 플로우차트 직접 그리기, 조건 수에 따른 규칙 폭발 계산, 미로 탐색(BFS·DFS)과 퍼지 세탁기 |
| 2 | 1편 2장 머신러닝 | 물고기 159마리 데이터로 손 규칙 vs 로지스틱 회귀 |
| 3 | 1편 3장 딥러닝 | 치와와·머핀 퀴즈, XOR을 층 쌓기로 풀기 |
| 4 | 1편 4장 강화학습 | 미로 Q러닝, ε 바꿔 보기, 보상 해킹 사례 토론 |
| 5 | 1편 5장 단어 벡터 | 단어 계산기(king − man + woman), BPE 손으로 해 보기 |
| 6 | 1편 6장 트랜스포머 | bank의 두 얼굴 어텐션 실험 |
| 7 | 1편 7장 스케일링 | GPT-3 계산량 어림, 창발 찬반 토론 |
| 8 | 중간 점검 | 1편 1~7장 확인 문제 + "갑자기의 정체" 한 장 요약 쓰기 |
| 9 | 1편 8장 RLHF | 직접 라벨러 되기, 보상모델의 아첨 문제 |
| 10 | 1편 9장 추론 모델 | "차근차근" 한 줄 실험, GRPO 아하 순간 |
| 11 | 2편 1장 에이전트 | ReAct 한 걸음씩, 부록의 실제 API 예제(키가 있는 경우) |
| 12 | 2편 2장 컨텍스트·하네스 | 컨텍스트 창 꾸리기, 권한 문지기 정책 만들기 |
| 13 | 2편 3장 루프 | 멈춤 조건 설계, 외부 검증기 켜고 끄기 |
| 14 | 2편 4·5장 오케스트레이션·자가개선 | Anthropic vs Cognition 찬반 토론, 스킬 서랍 실험 |
| 15 | 2편 6장 종합 · 기말 발표 | 현장 도입 체크리스트로 자기 업무 에이전트 설계안 발표 |

기업 특강은 회당 3시간, 4회로 묶습니다. 수식과 코드는 건너뛰고 빠른 경로와 도판 조작을 중심으로 진행합니다.

| 회차 | 주제 | 다루는 장 | 마무리 활동 |
| --- | --- | --- | --- |
| 1 | 규칙에서 학습으로 | 1편 1~4장 | 우리 회사 업무 중 규칙으로 충분한 일, 학습이 필요한 일 나눠 보기 |
| 2 | LLM은 왜 갑자기 나왔나 | 1편 5~7장 | "갑자기가 아니었던 다섯 가지 재료" 한 장 요약 |
| 3 | 길들이기와 추론, 그리고 일하는 AI | 1편 8·9장, 2편 1장 | 에이전트에게 맡길 후보 업무 고르기 |
| 4 | 맡기되 선을 긋는 법 | 2편 2~6장 | 현장 도입 체크리스트 워크숍 |

## 장별 안내: 1편

1편의 핵심 질문은 "규칙을 누가 쓰는가"입니다. 장마다 답이 사람 → 데이터 → 보상 → 글과 사람의 선호로 바뀝니다.

| 장 | 학습 목표 | 토론 질문 | 과제 아이디어 | 자주 나오는 오개념 |
| --- | --- | --- | --- | --- |
| [1장 태엽 기계](../1-1_rulebase.html) | 전문가 시스템(지식 + 추론 엔진)을 설명하고, 규칙 폭발(2ⁿ)을 계산한다. 미로를 상태공간 그래프로 바꿔 BFS·DFS·최단 거리를 비교하고, 퍼지가 규칙의 경계를 부드럽게 만든 과도기 기술임을 안다 | 우리 회사에서 지금도 규칙으로 충분한 일은 무엇인가? | 실제 업무 하나를 IF-THEN 10줄로 써 보고, 예외를 찾아 보기 | "규칙 기반은 실패한 기술이다" → 경우의 수가 적은 곳에서는 지금도 가장 싸고 확실하다 |
| [2장 머신러닝](../1-2_machine_learning.html) | 학습을 "눈금을 데이터로 맞추는 일"로 설명하고, 훈련·시험 데이터를 나눠야 하는 이유를 안다 | 82.5%는 높은가, 낮은가? 누구에게, 어떤 일에서? | 다른 변수 조합으로 정확도가 어떻게 바뀌는지 코드 고쳐 보기 | "학습하면 다 맞힌다" → 결정트리도 틀렸고, 과적합이 따라다닌다 |
| [3장 딥러닝](../1-3_deep_learning.html) | XOR과 층 쌓기, 역전파의 뜻을 그림으로 설명한다 | 사람이 특징을 말로 설명 못 하는 업무는 무엇인가? | 치와와·머핀 퀴즈를 풀고, 틀린 칸이 왜 헷갈렸는지 써 보기 | "신경망은 뇌를 그대로 흉내 낸다" → 모양만 빌렸고 계산은 곱셈과 덧셈이다 |
| [4장 강화학습](../1-4_reinforcement_learning.html) | 보상·탐험·Q표를 설명하고, 보상 해킹 사례를 들 수 있다 | 우리 조직의 KPI는 어떻게 "해킹"될 수 있나? | 미로의 보상을 바꿔 에이전트가 이상한 길로 가게 만들어 보기 | "보상만 주면 원하는 대로 배운다" → 기계는 보상의 빈틈을 정확히 파고든다 |
| [5장 단어 벡터](../1-5_word_vectors.html) | 다음 단어 맞히기, 원-핫의 한계, 분포 가설, 토큰을 설명한다 | 사과를 먹어 본 적 없는 기계가 "안다"고 할 수 있는가? | 단어 계산기로 임의의 관계 3개를 시험하고 실패 사례를 기록하기 | "벡터가 뜻을 이해한다" → 함께 쓰이는 패턴을 담을 뿐이고, 편향도 담는다 |
| [6장 트랜스포머](../1-6_transformer.html) | Q·K·V 비유로 어텐션을 설명하고, 마스크가 GPT를 만드는 이유를 안다 | 같은 단어가 문맥마다 다른 뜻이 되는 우리 업계 용어는? | bank 실험을 다른 다의어로 바꿔 보기 | "어텐션만 있으면 된다" → 학습 전 어텐션은 the·on만 본다. 그릇과 학습은 다르다 |
| [7장 스케일링](../1-7_scaling.html) | 다섯 가지 재료, C ≈ 6ND, 창발 논쟁의 양쪽을 설명한다 | ChatGPT는 갑자기였나, 아니었나? | 다른 모델 하나의 학습 계산량을 공개 자료로 어림하기 | "크기만 키우면 된다" → 친칠라는 데이터도 함께 늘려야 한다고 보였다 |
| [8장 RLHF](../1-8_rlhf.html) | InstructGPT 3단계, 보상모델, 고삐 β, 아첨을 설명한다 | AI가 내 말에 맞장구칠 때 그것을 어떻게 알아챌까? | 같은 질문의 두 답에 순위를 매기고, 내 기준이 무엇이었는지 쓰기 | "RLHF는 모델을 똑똑하게 한다" → 주로 말하는 방식을 바꾼다 |
| [9장 추론 모델](../1-9_reasoning_model.html) | CoT·자기 일관성·추론 강화학습, 규칙 채점의 이유를 설명한다 | 풀이를 길게 쓴 답은 더 믿을 만한가? | 같은 산수 문제를 바로 답하게, 풀어서 답하게 해 비교하기 | "풀이가 곧 모델의 생각이다" → 풀이가 실제 이유를 말하지 않는 경우도 관찰됐다 |

## 장별 안내: 2편

2편의 핵심 질문은 "무엇을 맡기고, 어디서 멈추는가"입니다. 학습자가 자기 업무에 바로 적용해 보게 하는 것이 수업의 중심입니다.

| 장 | 학습 목표 | 토론 질문 | 과제 아이디어 | 자주 나오는 오개념 |
| --- | --- | --- | --- | --- |
| [1장 에이전트 모델](../2-1_agent.html) | ReAct(생각→행동→관찰)와 단계가 길수록 실패가 곱해지는 이유(pᵏ)를 설명한다 | 우리 업무 중 몇 단계짜리 일을 맡길 수 있는가? | 맡길 업무를 단계로 쪼개고, 단계별 성공률을 가정해 전체 성공률 계산 | "에이전트는 더 똑똑한 모델이다" → 같은 모델에 도구와 반복을 붙인 것이다 |
| [2장 컨텍스트·하네스](../2-2_context_harness.html) | 프롬프트·컨텍스트·하네스의 관계, Lost in the Middle, 권한 문지기를 설명한다 | 우리 에이전트가 절대 혼자 하면 안 되는 행동은? | 자기 업무용 "허용·승인 필요·금지" 행동 목록 만들기 | "프롬프트만 잘 쓰면 된다" → 무엇을 어디에 넣는지, 어떤 권한을 주는지가 더 크다 |
| [3장 루프 엔지니어링](../2-3_loop_engineering.html) | 네 가지 멈춤 조건과 외부 검증기의 역할을 설명한다 | "다 됐어요"를 믿어도 되는 상황은 있는가? | 업무 하나의 검증기와 멈춤 조건을 숫자로 설계하기 | "오래 돌리면 결국 된다" → 검증기 없는 루프는 비용만 늘거나 거짓 완료로 멈춘다 |
| [4장 오케스트레이션](../2-4_orchestration.html) | 나눠 하기의 이득(+90.2%)과 비용(약 15배 토큰), 반대 근거를 함께 설명한다 | 우리 팀의 일 분담에서 어긋남이 생기는 지점은? | Anthropic과 Cognition 글을 읽고 각자 어떤 일에서 옳은지 한 쪽지 쓰기 | "에이전트가 많을수록 좋다" → 얽힌 일에서는 하나가 더 정확하다 |
| [5장 자가개선 루프](../2-5_self_improving_loop.html) | 스킬·기억 파일이 고쳐지는 구조와 "검증 후 저장"의 필요를 설명한다 | 우리 조직의 업무 매뉴얼은 누가, 얼마마다 고치나? | 스킬 서랍 실험의 정책을 바꿔 보고 결과 해석하기 | "쓸수록 무조건 나아진다" → 검증 없이 쌓으면 틀린 습관도 굳는다 |

## 평가와 과제 운영

장 끝의 확인 문제는 수업 시작 5분 복습용으로 쓰고, 점수에는 넣지 않기를 권합니다. 문제와 해설이 페이지에 공개돼 있고, 보기를 누르면 바로 답이 보이기 때문입니다.

채점하는 과제는 AI가 대신 쓰기 어렵도록 세 가지를 넣습니다.

1. **자기 업무의 재료**: 학생·수강생이 실제로 하는 일을 예로 쓰게 한다.
2. **직접 돌린 실험의 숫자**: 페이지의 도판이나 코드에서 값을 바꿔 얻은 결과를 캡처와 함께 낸다.
3. **반대 주장 다루기**: 창발 논쟁(1편 7장), 멀티에이전트 찬반(2편 4장)처럼 양쪽을 두고 자기 입장을 정하게 한다.

기말 과제(업무 에이전트 설계안) 채점 기준입니다. 배점은 총 100점을 예로 들었습니다.

| 기준 | 배점 | 우수 | 미흡 |
| --- | --- | --- | --- |
| 맡길 일의 선택 | 20 | 결과를 규칙으로 확인할 수 있는 일을 고르고 이유를 단다 | 확인 방법 없이 "보고서 작성" 같은 넓은 일을 고른다 |
| 넘으면 안 되는 선 | 20 | 한도와 되돌릴 수 없는 행동을 IF-THEN으로 적고 승인 단계를 둔다 | 안전장치를 "주의한다"는 말로만 쓴다 |
| 검증기와 멈춤 조건 | 25 | 완료 판정 방법, 반복 한도, 비용 상한을 숫자로 정한다 | 에이전트의 자기 보고를 완료 기준으로 삼는다 |
| 기억·기록 관리 | 15 | 스킬 저장 기준, 감사 주기, 판단 근거 로그를 정한다 | 기억과 기록을 다루지 않는다 |
| 근거와 정직한 한계 | 20 | 시리즈의 장·출처를 인용하고 설계안의 한계를 적는다 | 근거 없이 성과를 장담한다 |

## 수업 준비물과 주의 사항

- **페이지 공개**: 저장소의 GitHub Pages로 공개하면 첫 화면(`index.html`)에서 15개 장으로 이동할 수 있습니다.
